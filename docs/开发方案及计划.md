# 群晖 Note Station 客户端（Note Station Plus）开发方案与计划

---

## 一、 项目背景与需求概述

本项目旨在针对群晖官方 Note Station 客户端功能单一、缺乏 Markdown 支持、无法同时多开多服务、无法跨服务同步笔记等痛点，基于群晖官方 Web API 重新实现一套现代化的跨平台桌面客户端。

### 核心需求清单

| 序号 | 需求项 | 详细描述 |
| :--- | :--- | :--- |
| **REQ-1** | **Markdown 格式编辑** | 提供流畅的 Markdown 双向/即时渲染编辑体验，支持代码高亮、数学公式、表格、任务列表及图文混排。 |
| **REQ-2** | **多服务同时登录与 Tabs 切换** | 允许用户同时配置并登录多个群晖 NAS Note Station 服务，顶部以 Tabs 形式随时切换不同服务工作空间。 |
| **REQ-3** | **跨服务便签同步** | 支持将当前服务的指定便签同步到其他已登录服务；根据“便签标题”进行匹配，若目标服务已存在同名便签则更新，若不存在则自动新建。 |
| **REQ-4** | **跨平台运行环境** | 适配 Windows 10、Windows 11 以及 Ubuntu Desktop 24，提供原生安装包（.exe / .deb / AppImage）。 |
| **REQ-5** | **官方 API 深度重构** | 完全基于群晖 DSM 官方 Web API（`SYNO.API.*`, `SYNO.NoteStation.*`）原生交互，不依赖已废弃的旧版 Chrome App 包装。 |

## 二、 可行性分析与实机验证结果

针对用户提供的测试服务及账户（服务1: `http://172.28.10.180:5000`，服务2: `http://172.28.10.182:5000`，账户: `notedev`），开发团队已进行了实机 API 连通性测试与核心逻辑探测，结论如下：

### 2.1 官方 API 接口可行性验证（100% 可行）
- **身份认证机制（`SYNO.API.Auth`）**：
  - 通过 `/webapi/auth.cgi` 成功完成 `version=3` 认证，获取独立 `sid` 与会话 Cookie，并能稳定维持会话与注销。
- **笔记本管理（`SYNO.NoteStation.Notebook`）**：
  - 实测调用 `method=list`（获取列表）、`method=create`（创建笔记本）、`method=delete`（删除笔记本）均成功返回并生效。
- **便签核心管理（`SYNO.NoteStation.Note`）**：
  - 实测调用 `method=list`、`method=get`、`method=create`、`method=set`（更新内容与标题）、`method=delete`（删除笔记）全链路走通。
  - 实测更新 `content` HTML 文本与 `title` 即时同步入库，返回正确的版本哈希 `ver` 与修改时间戳 `mtime`。

### 2.2 Markdown 格式兼容性方案（100% 可行）
- **存储机制**：群晖 Note Station 官方存储便签内容为标准 HTML 格式。
- **解决方案（高保真混成方案）**：
  1. **保存时**：将 Markdown 解析并编译为符合 Note Station 渲染规范的标准 HTML，保证群晖官方 Web 界面及移动端 DS note 能够正常排版阅读。
  2. **无损溯源**：在保存的 HTML 中以隐藏块或注释形式嵌入原始 Markdown 源文本（`<!-- note-station-plus:markdown\n...\n-->`），客户端再次加载时实现 100% 原始 Markdown 语法无损还原。
  3. **存量兼容**：对于原先在官方客户端创建的存量纯 HTML 笔记，采用 `Turndown` 引擎智能转为 Markdown，并允许用户一键升级为无损 Markdown 便签。

### 2.3 多服务多 Tab 会话隔离机制（100% 可行）
- 群晖 Web API 支持通过请求参数显式携带 `_sid`，且支持请求级独立 CookieJar / Session。
- 在客户端架构中，每个已登录的 Note Station 服务作为一个独立的 `SynoClientSession` 实例，持有专属的 `baseURL`、`account`、`sid` 与内存缓存树，Tabs 切换仅切换前端渲染绑定的 Context，各服务网络请求与会话严格物理隔离，绝不会发生串号或串会话问题。

### 2.4 跨服务便签同步逻辑闭环（100% 可行）
- **同步工作流**：
  1. 提取源便签的 `title`、Markdown 源码、标签、附件。
  2. 调用目标服务的 `SYNO.NoteStation.Note` `list` 检索标题完全一致的便签。
  3. 若命中已有便签，提取其 `object_id` 并调用 `method=set` 执行内容与元数据覆盖（或弹出 Diff 差异对比由用户确认）；若未命中，自动调用目标服务的 `method=create`，归属到目标服务的同名笔记本（如不存在则自动创建或落入默认笔记本）。
  4. 支持记录“同步映射表”，实现后续一键快速增量同步。

### 2.5 跨平台打包与运行环境（100% 可行）
- 采用 **Electron 32+ + Node.js 22 + Vite 6 + TypeScript** 现代架构。
- Windows 10/11: 使用 `electron-builder` 构建 NSIS 安装包及免安装便携版。
- Ubuntu Desktop 24: 构建原生 `.deb`（集成 Desktop 入口与图标）和免依赖 `.AppImage`。

**综合结论：本项目技术路径清晰，无底层阻碍，商业与技术完全可行！**

### 3.2 关键模块设计细节

#### 1. 多服务会话管理 (Multi-Service Session Manager)
- 每个服务节点数据结构：
  ```typescript
  interface ServerProfile {
    id: string;               // 唯一实例 UUID
    alias: string;            // 用户设置的别名，如 "公司 NAS", "家庭备份"
    serverUrl: string;        // 基础 URL，如 http://172.28.10.180:5000
    account: string;          // 用户名
    passwordEncrypted: string;// 基于系统 Keyring (safeStorage) 加密存储的密码
    sid?: string;             // 当前会话 Session ID
    isOnline: boolean;        // 在线状态
    lastActiveTime: number;   // 最后通信时间
  }
  ```
- **多 Tab 隔离**：应用顶部渲染动态 Tab，支持切换激活服务、双击重命名别名、右键快捷重连/断开、拖拽排序。

#### 2. Markdown 编辑引擎 (Markdown Hybrid Engine)
- **选型**：推荐采用 **Vditor** 作为前端核心编辑器。
  - 原生支持三种编辑模式：所见即所得 (WYSIWYG)、即时渲染 (Instant Rendering / IR)、分屏预览 (Split View)。
  - 内置支持 KaTeX 数学公式、Mermaid 流程图、GFM 任务清单、代码高亮、多级标题大纲。
  - 支持直接粘贴剪贴板截图并自动上传至当前 Note Station 服务的附件系统。
- **HTML <-> Markdown 双向互转管线**：
  ```
  Markdown 源码 ---> [Markdown-It + HTML Comment Wrapper] ---> Note Station HTML
  Note Station HTML ---> [检查隐藏 Markdown 块] 
                        ├─> 存在: 直接提取原始 Markdown (0损失)
                        └─> 不存在: 通过 Turndown 智能转换
  ```

#### 3. 跨服务便签同步模块 (Sync Coordinator)
- **同步工作流与规则矩阵**：
  1. **触发方式**：
     - 单篇主动同步：便签工具栏点击“同步到...”，勾选已登录的一个或多个目标服务。
     - 规则自动同步：可为指定便签绑定“关联目标服务”，每次按 Ctrl+S 保存时静默触发同步。
  2. **标题匹配与决策引擎**：
     ```mermaid
     flowchart TD
         Start["发起便签同步 (源便签: Title, Content)"] --> Query["向目标服务查询: 是否存在相同 Title 的便签?"]
         Query -->|不存在| Create["在目标服务同名笔记本中创建新便签"]
         Query -->|存在同名便签| Check{"目标便签内容是否一致?"}
         Check -->|一致| Finished["提示: 内容已是最新，无需更新"]
         Check -->|不一致| ConflictCheck{"冲突策略设置"}
         ConflictCheck -->|覆盖模式| Overwrite["调用目标服务 SYNO.NoteStation.Note.set 覆盖更新"]
         ConflictCheck -->|差异对比| DiffModal["弹窗展示 Diff 对比，由用户确认覆盖或另存新便签"]
         Create --> Success["记录同步关联与日志，完成"]
         Overwrite --> Success
         DiffModal --> Success
     ```

#### 4. 离线缓存与本地存储
- 采用本地轻量存储（IndexedDB + localStorage）缓存各服务便签列表与近期便签内容。
- 当网络波动或 NAS 临时离线时，允许只读浏览并支持离线保存草稿，待网络恢复后提示同步回 NAS。

## 四、 开发路线与时间计划表 (Development Schedule)

项目分为 **5 个冲刺阶段 (Sprints)**，预计总工期约为 **4~5 周**。

| 阶段 | 阶段目标 | 周期 | 核心交付内容 | 验收里程碑 |
| :--- | :--- | :--- | :--- | :--- |
| **Phase 1** | **基础设施与 API 通信层构建** | 第 1 周 | 1. 搭建 Electron + Vite + React/Vue3 + TS 工程框架<br>2. 封装 `SynologyApiService`（登录认证、Note Station 全部接口增删改查）<br>3. 实现安全密码存储与配置管理器 | 完成针对 180 与 182 服务的联调自动化单元测试（登录、列表、创建、删除验证） |
| **Phase 2** | **多服务管理与 Tabs 交互系统** | 第 2 周 | 1. 顶部多服务 Tabs 栏组件（添加/删除/重命名/拖拽排序）<br>2. 多账号独立 Session 上下文与网络隔离<br>3. 左侧笔记本树形分类与中间便签列表展示 | 支持在 UI 上同时连接两台群晖服务，随意切换 Tab 无卡顿、数据完全独立隔离 |
| **Phase 3** | **Markdown 编辑引擎与便签 CRUD** | 第 3 周 | 1. 集成 Vditor 编辑器，实现即时渲染与分屏模式<br>2. 实现 Markdown <-> Note Station HTML 双向转换及无损还原机制<br>3. 实现便签创建、重命名、编辑、自动保存草稿、删除 | 在任一服务内流畅编辑 Markdown，保存后在群晖官方 Web 界面排版整齐且本地能无损重新打开 |
| **Phase 4** | **跨服务便签同步引擎 (Sync)** | 第 4 周 | 1. 跨服务便签同步对话框（选择目标服务）<br>2. 标题匹配检索算法（存在则更新，不存在则新建）<br>3. 差异对比（Diff Viewer）与冲突处理机制<br>4. 同步历史与状态日志 | 选中 180 服务的便签，一键成功同步至 182 服务（新建/覆盖更新双场景实测验证） |
| **Phase 5** | **跨平台打包与集成测试** | 第 5 周 | 1. 适配 Windows 10/11 与 Ubuntu 24 系统外观、快捷键与托盘<br>2. `electron-builder` 配置与自动化构建脚本（.exe, .deb, AppImage）<br>3. 边界测试（断网恢复、大文本、特殊 Markdown 语法、异常处理） | Windows 10/11 与 Ubuntu 24.04 系统均可直接安装运行，功能全量验收通过 |

## 五、 关键技术风险与应对策略

| 风险项 | 潜在影响 | 应对防范措施 |
| :--- | :--- | :--- |
| **1. 会话过期与 Token 失效** | 长时间放置可能导致群晖 `_sid` 过期，后续保存便签报错。 | 在 API 通信拦截器中增加自动静默重试机制：当捕获到 `code: 105` 或认证过期时，自动使用缓存的凭据发起无感重新登录并重试原请求。 |
| **2. HTML 与 Markdown 转换失真** | 复杂排版在官方 DS note 与客户端之间反复编辑可能发生标记丢失。 | 采用**双轨存储设计**：提交给群晖的内容为标准 HTML（供外部应用查看），但内嵌加密或注释标记的原始 Markdown；编辑时优先读取原始 Markdown，确保源文本绝对无损。 |
| **3. 跨服务同步时标题重名与冲突** | 若目标服务存在多个同名便签，或本地与远端同时修改。 | 匹配时若发现多篇重名便签，弹出选择列表由用户指定；更新前校验版本修改时间戳，若检测到冲突则提供双栏 Diff 对比供用户抉择。 |
| **4. Ubuntu 24.04 打包兼容性** | Ubuntu 24 采用了较新的 GNOME 环境与沙箱安全策略（AppArmor 限制）。 | 打包配置针对 Debian/Ubuntu 24 优化配置，添加 `sandbox` 启动标志兼容与正确的 mime-types 声明，提供免依赖的标准 AppImage 与 native .deb 两种格式。 |
